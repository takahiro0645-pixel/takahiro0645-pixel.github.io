AIが書いたVBAは「テストでは動く」

ChatGPTやClaude、CopilotにExcel VBAを頼むと、すぐにそれらしいコードが返ってきます。手元の小さなデータで試すと、たいてい動きます。

ところが本番のファイルで動かすと、途中で止まったり、一部のデータが抜けていたりすることがあります。

原因の多くは、AIの性能ではなくこちらが伝えていない前提にあります。データにどんな汚れが混ざるのか、誰がどんな状況で実行するのか。AIはそれを知りようがありません。

この記事では、AIが書いたVBAを実務で使う前に確認したい7つの項目を、修正例とあわせて紹介します。

※コードは説明用に作成した例です。

確認1：範囲が数字で固定されていないか

For i = 2 To 100 や Range("A1:D500") のように、範囲が決め打ちになっていることがあります。テスト時の件数に合わせて書かれているだけなので、データが増えると抜けが出ます。

Dim lastRow As Long
lastRow = ws.Cells(ws.Rows.Count, 1).End(xlUp).Row
For i = 2 To lastRow
    ' 処理
Next i

最終行を取る列は、伝票番号のように必ず値が入る列を選びます。

確認2：SelectやActiveSheetに頼っていないか

Sheets("集計").Select → Selection.Value = ... のような書き方は、実行中に別のブックがアクティブになると、意図しないシートを書き換えるおそれがあります。

Dim ws As Worksheet
Set ws = ThisWorkbook.Worksheets("集計")
ws.Range("A2").Value = "合計"

ブックとシートを変数で明示するのが基本です。

確認3：文字列の数字や日付を想定しているか

自動化が止まる原因は、コードよりデータ側にあることが少なくありません。

  • 1200円、¥1,200、全角の １２００
  • 前後のスペース
  • #N/A などのエラー値

セルの値をそのまま計算に使うと、型エラーで止まります。IsError、IsNumeric、IsDate で確認してから使い、変換できない行は記録してスキップする形にしておくと安心です。

確認4：空白行と重複を想定しているか

人が入力した表には、途中の空白行や同じキーの二重入力が混ざります。重複を「スキップ」「上書き」「合算」のどれにするかは業務ルール次第なので、AIに依頼するときに指定してください。指定しないと、AIが勝手に決めてしまいます。

重複の検出には Scripting.Dictionary が便利です。

確認5：On Error Resume Nextで握りつぶしていないか

コードの冒頭に On Error Resume Next があると、エラーが起きても黙って次に進みます。止まらない代わりに、間違った結果がそのまま出力されます。

エラーを許容するのは「ファイルが開けないかもしれない」など必要な箇所だけにし、直後に On Error GoTo ErrHandler で戻します。

確認6：画面更新と計算モードを必ず戻しているか

高速化のために ScreenUpdating や計算モードを切り替えるコードはよくあります。問題は、エラーで止まったときに元に戻らない書き方です。

prevCalc = Application.Calculation
On Error GoTo ErrHandler
Application.ScreenUpdating = False
Application.Calculation = xlCalculationManual
' 処理
CleanExit:
    Application.Calculation = prevCalc
    Application.ScreenUpdating = True
    Exit Sub
ErrHandler:
    MsgBox "エラー " & Err.Number & "：" & Err.Description
    Resume CleanExit

正常終了でもエラーでも、必ず CleanExit を通る形にします。

確認7：パスの直書きと上書きの安全策

  • 個人PCのパスが直書きされていると、他の人の環境では動きません
  • 確認なしの全消去は、押し間違いでデータを失います
  • 読み込み元を通常モードで開くと、うっかり保存して壊すリスクがあります

フォルダはダイアログで選ばせる、消去前に確認メッセージを出す、読み込み元は ReadOnly:=True で開く、の3点を確認します。

最初の依頼で前提を渡しておく

7項目の多くは、依頼の段階で伝えれば最初から反映されやすくなります。たとえば次のような一文を依頼に加えます。

- Select / ActiveSheet を使わず、ブックとシートを変数で明示する
- 最終行はデータから取得し、範囲を固定しない
- 変換できない値や重複は止めずにスキップし、ログシートに記録する
- エラー時も画面更新と計算モードを元に戻す

なお、実際の顧客データや社外秘の数値はAIのチャットに貼らず、ダミーの値で列構成と汚れ方を伝えるようにしましょう。

まとめ

  • AIが書いたVBAは「テストデータで動く」までは早い
  • 本番で止まる原因は、範囲・参照・型・空白重複・エラー処理・設定の戻し忘れ・パスに集中しやすい
  • データの汚れ方と業務ルールを知っているのは自分だけなので、確認と修正は自分の担当と考える

エラーの読み方を体系的に押さえたい場合は、VBAのエラー対処を扱った書籍を手元に置いておくと、AIの回答が正しいかを判断する助けになります。
